# Opencaster feature support on Hypersnap

> **⚠️ AI-Generated**: May contain errors. Verify before use.

The [Farcaster client snapshot](https://github.com/farcasterxyz/client/tree/0c289ed93c125cc0f752d90ad224a4a41c31c3f5) is a UX reference. Its README says the snapshot points to production Farcaster APIs. Opencaster implements its own UI and uses the fixed Hypersnap gateway; importing the snapshot's services would violate that boundary.

This matrix records the implementation reviewed against [Hypersnap source](https://github.com/farcasterorg/hypersnap/tree/2e8733d044141ad3ba0e0592a4d5873c1dc6ce9c), version 0.13.5. An endpoint name alone does not establish support. Public reads were also checked against the live node; signed writes were tested only with synthetic accounts on an OS-sandboxed loopback node.

Unsupported hosted features are not presented as working controls: Farcaster DMs, managed account registration, push delivery, miniapp execution/catalogs, trading, video processing, paid storage, protocol pins, channel subscription management or a personalized recommendation model. Some require new first-party infrastructure; others require missing Hypersnap protocol/index support. Following suggestions, quotes and channel participation reads, when shown, are bounded views of the current node's indexes rather than promises of a complete archive.

Reusable validation, route and local-storage helpers in `hypersnap/src/lib/` are candidates for a future shared Hypersnap mobile package. Opencaster's helpers and protocol code remain local to this client, with no Quorum messenger runtime dependency.

The reviewed Hypersnap `api/http.rs::resolve_cast` and `network/server.rs::find_cast_fid_by_hash` use exact 20-byte hashes; the latter rejects shorter input. `network/http_server.rs` serves `/v1/castsByFid` from the author's retained cast-add and cast-remove history. The gateway permits only fixed 250-message reverse pages with canonical base64 cursors. Each lookup batch checks at most four pages under one 25-second deadline and hydrates matching full hashes against the resolved author FID with at most four concurrent reads. The lookup publishes verified candidates after each fully validated matching page. When a snapshot contains one available match, the client opens it and cancels the remaining lookup; opening the first available match makes no claim about collisions in unsearched history. Multiple returned matches remain an explicit choice. Within one batch, progress and final results reuse their exact author/hash reads; choosing a full cast also cancels the remaining lookup. Explicit continuation retains only public lookup metadata in tab memory, rechecks the author mapping, validates the native FID/store/timestamp/hash cursor against descending receipts, detects cursor cycles, and stops at 100,000 history messages or 400 cursors and 25 candidates. Those bounds are not a claim of a complete network archive or a new node prefix index.

## Composer walkthrough on Farcaster and X · 2026-10-21

The owner requested a Chrome inspection of both existing signed-in websites. Separate tabs opened the empty [Farcaster composer](https://farcaster.xyz/) and [X post dialog](https://x.com/compose/post). Farcaster placed one editor above a compact media/emoji/channel row with a clear Cast action and nearby Drafts. X placed one editor above a compact attachment row and right-aligned Post action, with Drafts available separately. No text, file, post, cast, wallet approval, audience change or account setting was submitted. Temporary reference tabs were closed; account/feed content is not included in this record.

Quorum adopts that writing-first hierarchy through independently implemented React components: one growing editor, compact photo/GIF-file, mention, emoji and draft controls, on-demand panels, attachment previews and a clear publish action. The public-upload/retained-metadata notice remains visible before an upload or paste. Details and limits are available through Media info. Reply, quote and channel destinations retain their existing signed-message contracts; publication remains an explicit action.

Only already supported attachment types are exposed. A GIF is a selected/uploaded image file, not a hosted GIF search integration. Emoji insert ordinary Unicode text locally. Links remain text, without a remote preview fetch. The current client keeps its existing two-embed cap, shared by images and quotes; this is a client limit, not a claim about every Hypersnap protocol version. Video processing, polls, scheduling, location attachments and remote media catalogs require separate implementations and are not offered as working tools.
